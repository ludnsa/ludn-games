# تحدي الفئات (quiz-grid)

لعبة لوحة فئات: فريقان، 6 فئات × 6 أسئلة (200/200/400/400/600/600 = 36 سؤالاً)، مع ثلاث وسائل مساعدة لكل فريق.

- شاشة الحكم: `/games/quiz-grid`
- شاشة اللاعبين: `/games/quiz-grid/join` (بدون تسجيل دخول)
- لوحة التحكم: `/admin/quiz-grid`

> **الاسم والـ slug مؤقتان.** كلاهما معرّف في [`constants/quiz-grid.ts`](../constants/quiz-grid.ts).
> لتغيير الاسم العربي عدّل `QUIZ_GAME.title` فقط. تغيير الـ slug يتطلب أيضاً إعادة تسمية
> مجلدات `app/games/quiz-grid` و `app/admin/quiz-grid`، وتغيير `QUIZ_GAME.id` يعني أن سجلات
> `user_games` القديمة لن تُطابق اللعبة.

---

## 1. تشغيل الميجريشن

المستودع لا يستخدم Supabase CLI، والجداول الحالية طُبّقت يدوياً. لذلك الميجريشن ملف SQL عادي:

1. افتح **Supabase Dashboard → SQL Editor**.
2. انسخ محتوى [`supabase/migrations/0001_quiz_grid.sql`](../supabase/migrations/0001_quiz_grid.sql) كاملاً والصقه.
3. شغّله. الملف قابل لإعادة التشغيل (idempotent) — تكرار التشغيل لا يسبب أخطاء.

الملف ينشئ:

| الجدول | الغرض |
|---|---|
| `quiz_categories` | الفئات |
| `quiz_questions` | بنك الأسئلة |
| `quiz_rooms` | الجلسة: الأسماء، النقاط، الدور، وسائل المساعدة، المؤقت |
| `quiz_session_questions` | لقطة الـ 36 خلية لكل جلسة |
| `quiz_session_players` | اللاعبون المنضمّون |

بالإضافة إلى: فهرس `(category_id, points)`، قيد فريد على `external_ref` (عندما لا يكون NULL)،
إضافة `quiz_rooms` و `quiz_session_players` للبث اللحظي، وإنشاء bucket خاص باسم `quiz-media`.

### التحقق بعد التشغيل

```sql
-- الجداول والفهارس
select tablename from pg_tables where schemaname='public' and tablename like 'quiz%';
select indexname from pg_indexes where tablename='quiz_questions';

-- السياسات: يجب ألا تظهر أي سياسة لـ quiz_session_questions
select tablename, policyname from pg_policies where tablename like 'quiz%';

-- الـ bucket يجب أن يكون خاصاً (public = false)
select id, public from storage.buckets where id='quiz-media';
```

**أهم فحص أمني:** من متصفح غير مسجّل دخول على `/games/quiz-grid/join`، جرّب في الـ console:

```js
// يجب أن يعيد صفراً من الصفوف أو خطأ صلاحيات
await getSupabaseBrowser().from('quiz_session_questions').select('*')
```

هذا الجدول هو المكان الوحيد الذي تعيش فيه نصوص الإجابات أثناء الجلسة، وهو مغلق تماماً على العميل.

## 2. استيراد المحتوى

### أ. سكربت الاستيراد

```bash
# معاينة بدون كتابة أي بيانات
npm run import:quiz -- supabase/seed/quiz-sample.csv --dry-run

# استيراد فعلي
npm run import:quiz -- ./content/questions.csv

# يقبل JSON أيضاً بنفس أسماء الأعمدة
npm run import:quiz -- ./content/questions.json
```

يقرأ السكربت `NEXT_PUBLIC_SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` من `.env` تلقائياً.

ما يفعله:

- يتحقق من كل صف: النقاط ∈ {200، 400، 600}، النصوص غير فارغة، وملفات الصور موجودة فعلاً على القرص.
- **لا يكتب شيئاً إن وُجد خطأ واحد** — يطبع كل الأخطاء بأرقام أسطرها ويخرج برمز 1.
- ينشئ الفئات الناقصة (باسم عربي مبدئي = الـ slug، عدّله من لوحة التحكم).
- يحوّل الصور إلى WebP بحد أقصى 1600px للضلع الأطول ويرفعها إلى `quiz-media`.
- يحدّث الصفوف التي تحمل `external_ref` بدل تكرارها، فإعادة الاستيراد آمنة.
- يطبع جدول تغطية لكل فئة، **ويخرج برمز 1** إذا نقصت أي فئة عن سؤالين في أي قيمة نقاط.

### ب. لوحة التحكم

`/admin/quiz-grid` — محمية بنفس صلاحية المدير المستخدمة في بقية اللوحة
(`app_metadata.role === 'admin'`، انظر [`middleware.ts`](../middleware.ts)).

- إضافة/تعديل/حذف الفئات والأسئلة.
- رفع الصور مع معاينة — التحويل إلى WebP يتم **داخل المتصفح** قبل الرفع.
- تصفية حسب الفئة، قيمة النقاط، وحالة التفعيل، مع بحث نصي.
- رفع جماعي من CSV بنفس قواعد التحقق المستخدمة في السكربت (ملف مشترك: [`lib/quiz-import.ts`](../lib/quiz-import.ts)).

> الرفع الجماعي من اللوحة **للنصوص فقط**. لاستيراد الصور مع الأسئلة استخدم السكربت.

## 3. صيغة ملف CSV

```csv
external_ref,category_slug,question_text,answer_text,points,question_image,answer_image
GEN-001,history,من هو مؤسس الدولة السعودية الأولى؟,الإمام محمد بن سعود,200,,
GEN-002,history,ما اسم هذه المدينة؟,الدرعية,400,images/diriyah.jpg,images/diriyah-answer.jpg
```

| العمود | إلزامي | ملاحظات |
|---|---|---|
| `external_ref` | لا | مفتاح التحديث عند إعادة الاستيراد. **بدونه يُضاف السؤال كسجل جديد في كل مرة.** |
| `category_slug` | نعم | تُنشأ الفئة تلقائياً إن لم تكن موجودة |
| `question_text` | نعم | |
| `answer_text` | نعم | |
| `points` | نعم | 200 أو 400 أو 600 فقط |
| `question_image` | لا | مسار محلي **نسبةً لمجلد ملف الاستيراد** |
| `answer_image` | لا | نفس الشيء |
| `question_image_alt` | لا | وصف عربي للصورة |
| `answer_image_alt` | لا | وصف عربي للصورة |

العناوين العربية المُصدَّرة من لوحة التحكم مقبولة أيضاً، وكذلك ملف بلا سطر عناوين إذا كان الترتيب مطابقاً.

## 4. إضافة فئة جديدة

الطريقة الأسهل: `/admin/quiz-grid` ← **إدارة الفئات** ← اكتب الاسم العربي ← إضافة.
ثم أضف لها **سؤالين على الأقل من كل قيمة** (200، 400، 600) — أي 6 أسئلة كحد أدنى.

الفئة التي لا تحقق هذا الشرط تظهر في شاشة الحكم **معطّلة وغير قابلة للاختيار**، وتُعلَّم في
لوحة التحكم بشارة حمراء. هذا مقصود: كل عمود في اللوحة يحتاج 6 أسئلة بالتوزيع الثابت
200/200/400/400/600/600.

بديلاً، أي `category_slug` جديد في ملف الاستيراد يُنشئ الفئة تلقائياً باسم عربي مبدئي = الـ slug.

## 5. القرارات المسجّلة

الحالات التي اختلف فيها التنفيذ عن نمط سائد في المستودع، أو التي كانت المواصفة فيها غامضة:

### الكتابة من السيرفر حصراً
الألعاب الثلاث الحالية تكتب النقاط من المتصفح مباشرة بمفتاح anon
(انظر `hooks/games/auction/useAuctionReferee.ts`). هذه اللعبة **لا تفعل ذلك**: كل تعديل على
الجلسة يمر عبر Server Action في [`actions/quiz-grid.ts`](../actions/quiz-grid.ts) التي تتحقق
من أن المستخدم هو `host_user_id` للغرفة، وتحسب النقاط من قيمة الخلية المخزّنة في قاعدة
البيانات لا من حمولة العميل. السابقة موجودة في `actions/world-domination.ts` و
`app/actions/gameAccess.ts`.

### المؤقت مبني على وقت الانتهاء
لعبة المزايدات تكتب المؤقت لقاعدة البيانات كل ثانية. هنا نخزّن `question_deadline_at` مرة
واحدة، وكل جهاز يحسب الثواني المتبقية محلياً. الكتابة تحدث فقط عند بدء السؤال أو عند
إضافة 30 ثانية. الفرق: ~2160 كتابة لكل جلسة مقابل ~72.

### توقيت وسائل المساعدة
"كشف السؤال" في المواصفة = لحظة عرض نص السؤال على الشاشة (وليس كشف الإجابة). عليه:

- **الحفرة** تُستخدم من شاشة اللوحة، قبل اختيار الخلية — رهان أعمى.
- **اتصال بصديق** و **استريح** تُستخدمان أثناء عرض السؤال.

التوقيت مفروض **على السيرفر** في `activateQuizLifeline`، لا بتعطيل الأزرار فقط.

### احتساب "الحفرة"
إذا أجاب الفريق صاحب الحفرة إجابة صحيحة: يكسب قيمة السؤال ويخسر الخصم نفس القيمة.
إذا أخطأ: لا شيء يحدث. إذا أجاب **الفريق الخصم** إجابة صحيحة فيأخذ النقاط بشكل طبيعي —
الحفرة تعدّل النتيجة فقط عندما يكون صاحبها هو المُجيب الصحيح.

### ملخص الجلسة
لم نُنشئ جدولاً منفصلاً للملخص. النتيجة النهائية تُكتب على صف `quiz_rooms` نفسه:
`winner_team` (0 = تعادل) و `ended_at` بالإضافة إلى النقاط النهائية. هذا أبسط خيار يحقق
المطلوب.

### وصف الصور في ملفات الاستيراد
المواصفة تشترط وصفاً عربياً لكل صورة، لكن قائمة أعمدة CSV فيها لا تتضمن أعمدة الوصف.
الحل: العمودان `question_image_alt` و `answer_image_alt` اختياريان؛ إن غابا مع وجود صورة
يُشتق الوصف من نص السؤال/الإجابة ويُطبع تنبيه. **في لوحة التحكم الوصف إلزامي** عند إرفاق صورة.

### لوحة التحكم على `/admin/quiz-grid`
المواصفة اقترحت `/admin/quiz`، لكن المستودع يستخدم مسار مطابق لاسم اللعبة
(`/admin/auction`، `/admin/castle-war`). اتبعنا نمط المستودع.

### مجلد الميجريشن
المستودع لا يحتوي على `supabase/` ولا CLI ولا أنواع مولّدة — الأنواع مكتوبة يدوياً في
`types/index.ts`. أبقينا على النمط نفسه: SQL يدوي + أنواع مكتوبة يدوياً.

## 6. ملف العيّنة

[`supabase/seed/quiz-sample.csv`](../supabase/seed/quiz-sample.csv) يحتوي على **فئتين فقط**
(`sample-general` و `sample-science`) بـ 6 أسئلة لكل منهما، وكل سؤال مسبوق بكلمة **(عيّنة)**.

هذه بيانات تطوير مؤقتة وليست بنك أسئلة حقيقي — المحتوى الفعلي يورّده مالك المنتج.
احذف الفئتين من لوحة التحكم قبل الإطلاق.
