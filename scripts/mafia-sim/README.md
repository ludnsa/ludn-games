# محاكي المافيا

يلعب آلاف الجولات الوهمية على **كود اللعبة الحقيقي نفسه** (`actions/mafia.ts` و `lib/game/mafia-engine.ts`)
فوق قاعدة وهمية في الذاكرة وساعة وهمية. ما يتصل بأي قاعدة حقيقية ولا يحتاج `.env`.

## التشغيل — قبل أي رفع يمس المافيا

```bash
npm run sim:mafia            # كامل (دقائق): كل الأعداد 7–20 والنمطين، وكل تركيبات الفئات عند 9 و13 و17 لاعب
npm run sim:mafia -- --all   # كل تركيبة × كل عدد مافيا (ساعة ونصف تقريباً)
npm run sim:mafia:quick      # أسرع (أقل من دقيقة): عينة من التركيبات
npm run sim:mafia -- --seed 7              # عشوائية ثابتة قابلة للتكرار
npm run sim:mafia -- --games 3000 --fair 20000
npm run sim:mafia -- --only 3,4            # أقسام معيّنة بس (للتجربة وقت التطوير — قبل الرفع لازم الكامل)
```

يطلع بخطأ (`exit 1`) وسطر يبدأ بـ `FAIL` لو:

- علقت مرحلة (ما مشت مع إن الكل اختاروا، أو خلص المؤقت، أو تخطى المنشئ).
- جولة ما انتهت بفائز.
- انكشف دور لغير صاحبه: حالة أي لاعب (`getMafiaMyView`) فيها دور غيره، أو أسماء المافيا لغير مافيا،
  أو نتيجة تحقيق لغير المحقق، أو `final_roles` قبل النهاية.
- انحياز في التوزيع (|z| فوق 5 عبر عشرات الآلاف من التوزيعات)، أو في قائد المافيا بالليلة الأولى.
- سيناريو من سيناريوهات الساحر فشل.
- ضغطة تمويه بلحظة انتقال قرار المافيا انحسبت قتل، أو إعادة إرسال لاختيار ما رجعت نفس الرد.
- ضغطة منشئ (ابدأ، تخطي، ابدأ النقاش، ذبح الغشاش/الممنوع، جولة جديدة) وصلت مرتين ونقلت الغرفة مرحلتين،
  أو رجّعت رد غير الأول، أو "ابدأ" المكررة حجزت لعبتين أو كتبت توزيع غير فئات الإعداد، أو الذبح طلع إعلانه مرتين.
- صوت وصل مرتين وانحسب مرتين، أو عداد التصويت اللي تشوفه الجوالات ما يطابق الأصوات، أو إعادة صوت بعد ما خلص
  التصويت رُفضت أو غيّرت النتيجة.
- التصويت السري: اسم مصوّت انكتب بالغرفة (`vote_voters` توصل لكل الجوالات). والمكشوف: الأسماء ما تطابق الأصوات.
- اختيار الشيخ المكرر انرفض أو ما انحفظ صف واحد على آخر اختيار، أو طلب متأخر من صباح قديم انحفظ بصباح اليوم.

## الأقسام

1. **كل التركيبات**: جولة لكل (عدد لاعبين × عدد مافيا × مجموعة فئات إضافية × نمط). الكل يختار بسرعة.
   الأعداد الفردية بالتصويت السري، والزوجية مكشوف.
2. **جولات مشاغبة**: جوالات تتأخر أو تنقطع، لاعبين ما يختارون، منشئ يتخطى بدري، "جولة جديدة بنفس اللاعبين"،
   وانتقال قرار المافيا لعضو ثاني. يطبع التوزيع حسب المقعد وقائد الليلة الأولى. إعدادين من الأربعة بالتصويت السري.
3. **الساحر**: ياخذ كل فئة (المحقق/الطبيب/الجندي) ويلعب بها بنفس الليلة، صاحب الفئة يموت بانفجار المنتقم بالليل
   (يفتح البطاقة مثل الذبح)، ما يُعرض عليه مكان محقق طلع بالتصويت، ما يختار (الخيار يظل)، جواله ما توصله الشاشة
   (النظام ما يختار عنه)، يختار ويموت بنفس الليلة (إعلان موته + "الساحر اختار فئة" مع بعض)، ماتوا اثنين يختار وحدة.
   السريع: شاشة وحدة — بطاقة وحدة أو أكثر، والشخص بنفس الطلب (الجندي: الدرع بس)، وبدون مهمة ثانية.
   وفي كل جولة فيها ساحر: إعلان "الساحر اختار فئة" يطلع مرة وحدة بس بصباح ليلة اختياره، بدون ذكر أي فئة.
   الساحر اللي يصير جندي ياخذ درع جديد: يهاجمونه بنفس الليلة (ينجو بإعلان الجندي) أو بليلة بعدها (ينجو)،
   وبالهجوم الثاني يموت — مرة وحدة بس.
4. **انتقال قرار المافيا وإعادة الإرسال**: القائد ما وصلته الشاشة، وعضو ثاني شاشته على سؤال التمويه: ضغطته توصل
   كتمويه قبل الانتقال أو بنفس اللحظة أو بعده — لازم ما تنحسب قتل، والقتل يكون على اختياره بعد ما تمر ثانية ونص.
   وجولات كل اختيار فيها ينرسل مرتين (بنفس اللحظة وبعد المهلة، حتى بعد ما تتغير المرحلة): الإعادة تنجح مثل الأول
   وبنفس النتيجة. ومعها كل صوت وكل ضغطة منشئ ينرسلون مرتين (بنفس اللحظة، وبعد ما ردت الأولى والمرحلة تغيّرت)،
   والمنشئ يذبح وسط النقاش أحياناً، واختيار الشيخ ينرسل مرتين ومعه أحياناً طلب متأخر من صباح أمس، و"جولة جديدة" بنفس الغرفة 3 مرات. (الجولات المشاغبة فيها إعادة إرسال بنسبة 15%.)
5. **العدالة**: `buildRoleDeck` و `mafiaLeaderId` الحقيقيين — كم مرة طلع كل مقعد كل فئة، ومين يقود المافيا.
6. **كتابات متأخرة**: كل كتابة على الغرفة فيها موعد نهاية (كل انتقال لمرحلة بمؤقت، وبداية مؤقت الليل السريع) تعلق
   بالطريق 10–20 ثانية. مع `0019_mafia_deadline_at_write` (القاعدة الوهمية تقلّده): كل مرحلة لازم توصل بوقتها كامل
   من لحظة ما تنكتب، والأصوات قبل نهاية الوقت الكامل بثانية تنقبل، ومؤقت الليل السريع يبدأ مرة وحدة بالليلة، وكل
   كتابة موعد معها لحظة حسابها. ونفس الجولات على قاعدة بدون 0019 لازم تطلع المشكلة (مراحل ناقصة وأصوات مرفوضة)،
   وإلا القسم يفشل لأنه ما يفحص شي.

## كيف يشتغل

- `fakes/fake-supabase.ts`: قاعدة في الذاكرة تقلّد PostgREST بالقدر اللي يستخدمه الكود (القيود، الحذف المتسلسل،
  المرشّحات ومسارات JSON، `upsert` بـ `onConflict`، رموز الأخطاء). كل عملية تنتظر دورة عشان الطلبات المتزامنة تتداخل، و`jitterTurns` يخلط ترتيبها عشوائياً بدون تأخير حقيقي.
- `fakes/supabase-server.ts` و `game-access.ts` و `game-sessions.ts`: بدائل لملفات السيرفر (مفتاح الخدمة، الحساب،
  الاشتراك، جلسات اللعب). تنحمّل مكان الأصلية عبر `paths` في `tsconfig.json` هنا — كود اللعبة نفسه ما يتغير.
- `sim.ts`: "الأجهزة": كل لاعب يستدعي نفس الدوال اللي يستدعيها الجوال، والمنشئ أزراره. الساعة وهمية (`Date.now`)
  فالمؤقتات تمشي بدون انتظار حقيقي.
- `fairness.ts`: الإحصاء (z لكل مقعد وفئة).

ملاحظة: `scripts/` خارج `tsconfig.json` الرئيسي؛ فحص الأنواع للمحاكي: `npx tsc --noEmit -p scripts/mafia-sim/tsconfig.json`.

## جداول العدالة لحالها

```bash
npx tsx --tsconfig scripts/mafia-sim/tsconfig.json scripts/mafia-sim/run-fairness.ts 10000
npx tsx --tsconfig scripts/mafia-sim/tsconfig.json scripts/mafia-sim/run-fairness.ts 100000 --deck   # التوزيع بس، بعدد كبير
```

يطبع لكل إعداد (7–20 لاعب، 2–4 مافيا، بدون فئات ومع كل الفئات) كم مرة طلع كل مقعد مافيا وأكبر انحراف لكل فئة،
ثم نفس الشي عبر المسار الكامل (`startMafiaGame`: أول جولة، "جولة جديدة بنفس اللاعبين"، "غرفة جديدة")،
ثم قائد المافيا بالليلة الأولى: الكود القديم (ترتيب المقاعد) مقابل البذرة العشوائية.
لو طلع إعداد بانحراف بين 4 و5 مع 10,000 (يصير بالصدفة مع ~800 قيمة)، أعده بـ `100000 --deck`: الانحياز الحقيقي يظل ويكبر، والصدفة تختفي.
